Shadows

Four elevation levels. Higher levels should be used sparingly — modals and floating panels only. Most widget cards use lv-1.

AvaloniaUI

Use the BoxShadow property on Border (available in Avalonia 11+). The syntax is BoxShadow="0 2 4 0 #24000000" where the last segment is an ARGB hex color. Elevation lv-3 and lv-4 are best achieved with two comma-separated shadow values on a single Border. Note: Avalonia doesn't support spread radius — simulate with a slightly larger blur.

lv-1: Default widget cards, list items, surface cards
lv-2: Dropdowns, popovers, tooltips
lv-3: Side panels, drawers, contextual overlays
lv-4: Full-screen modals, game detail panels

Sparkline

A minimal time-series chart used to show trend without axis labels. Always paired with a current-value Stat Display above it. The fill area uses 7–8% opacity of the stroke color.

Color
Fill
AvaloniaUI

Use a Canvas with two Path controls — one for the line (stroke only), one for the filled area (fill only, low opacity). Generate the StreamGeometry path string in the ViewModel from a ring buffer of data points, normalized to canvas height. For smooth updates, throttle redraws to ~10fps using a DispatcherTimer. Buttons

Four button families serve different hierarchy levels. The inline link button ( .w-link ) lives exclusively in widget headers. Outlined action buttons appear in bodies and panels. Carousel buttons ( .ds-carousel-btn ) are purpose-built for hero slides — a filled primary whose background is overridden per-slide to match the tag accent, plus a translucent ghost. Avoid filled/solid action buttons except for destructive confirmation flows and carousel CTAs.

State
AvaloniaUI

Define a base Button ControlTheme with IsPointerOver and IsPressed visual states. Derive the three variants (Default, Primary, Ghost) as separate ControlTheme entries that inherit from the base. The inline link button ( w-link ) should be a styled Button with Padding=0, Background=Transparent, and BorderThickness=0 so it behaves as inline text.

Link buttons (.w-link) are for navigation — always in widget header label bars, never in content areas
Outlined buttons (primary variant) are for primary actions within a panel or widget body
Ghost buttons are for secondary or tertiary actions where visual weight should be minimized
Carousel buttons use Barlow Condensed 11px/700 at 0.07em tracking — slightly larger and heavier than action buttons to read over image backgrounds
Carousel primary bg should match the slide's tag color; for light accent colors (green, pink) set color:var(--bg-base) for contrast
All button text is uppercase mono — never title case or sentence case
Font size is always 10px (caption) with 0.06em letter spacing for action buttons; 11px with 0.07em for carousel buttons

Toggles

Two toggle patterns handle binary and multi-option selection. The Toggle Switch is a compact on/off pill for enabling features and settings. The Segmented Toggle is a grouped selector for 2–4 mutually exclusive modes. Both use accent color for the active state and transition smoothly between states.

Type
AvaloniaUI

The toggle switch maps to a styled ToggleSwitch control — override the KnobTransitions with a var(--dur-normal) TranslateTransform.X animation. Set OnContent and OffContent to empty for the minimal pill look. The segmented toggle is a RadioButton group inside a Border with CornerRadius 6. Bind IsChecked to a shared enum property; style each item with a DataTrigger on IsChecked to swap Background between transparent and the accent color.

Toggle switch: Use for binary on/off settings where the change takes effect immediately. Never use for actions that require a confirmation step.
Segmented toggle: Use for 2–4 mutually exclusive options. If more than 4 options are needed, use a dropdown or radio group instead.
Default state: Toggle switches default to "on" (accent bg, knob right). Add the .off class for the off state.
Label placement: Always pair toggles with a text label to the left. Never rely on the toggle alone to communicate what it controls.
Sizing: Toggle switch is 32 × 18px — do not resize. Segmented toggle width is determined by content; keep option labels short (1–2 words).

Two selection patterns for option groups and content filtering. Pills are compact rectangular selectors for modes and categories (layout density, time ranges). Filter Chips are rounded selectors for content filtering (library genres, shop categories). Both use single-select semantics — clicking one deactivates its siblings.

Type
AvaloniaUI

Both pills and filter chips map to a RadioButton group styled with a custom ControlTheme . Set GroupName to scope mutual exclusion. Use the IsChecked visual state to swap between default and accent backgrounds. Wrap in a horizontal WrapPanel with Spacing="5" . The pill variant uses CornerRadius="4" ; the filter chip uses CornerRadius="20" .

Pills vs. filter chips: Use pills for mode selection within settings or configuration panels. Use filter chips for content-level filtering where the user is narrowing a visible set of items.
Single select: Both are single-select by default — clicking one deactivates siblings. If multi-select is needed, use checkboxes instead.
Default selection: Always start with one pill/chip active. Never present a group with nothing selected.
Label length: Keep labels to 1–2 words. Truncate with ellipsis if content overflows 80px.
Group size: 3–7 items is ideal. For more than 7, consider a dropdown or scrollable chip row.
